# Ficha 360 do Eleitor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar localmente uma ficha unica do eleitor com cadastro, indicadores, timeline e registros relacionados.

**Architecture:** Um service de leitura agrega entidades existentes por `accountId` e `contactId`, sem duplicar dados. Uma rota autenticada entrega contrato normalizado e uma pagina React dedicada apresenta resumo, timeline e abas por dominio.

**Tech Stack:** TypeScript, Express, PostgreSQL/Drizzle, React, TanStack Query, Wouter, Vitest e Playwright.

## Global Constraints

- Nao criar nova tabela ou copiar dados dos modulos de origem; apenas adicionar `contact_id` as assinaturas.
- Toda consulta deve aplicar `accountId` e `contactId`.
- Limitar timeline a 100 itens e cada lista de dominio a 50 registros.
- Reutilizar componentes e tokens visuais existentes.
- Nao publicar, enviar ao GitHub ou alterar o ambiente de producao.
